# 分布式文件夹记忆系统

## 概述

本项目使用**分布式文件夹记忆系统**替代传统的单一 JSON 文件存储历史记忆。所有记忆按时间先后拆分为独立的 Markdown 文件，配合轻量级 JSON 索引，减少 Token 消耗，提高检索效率。

## 目录结构

```
Ai记忆库/
├── 索引.json          # 轻量总目录，仅映射当前未压缩（最新 20 条）记忆
├── 记忆_001.md        # 第 1 条记忆（活跃状态，最多 20 个）
├── 记忆_002.md        # 第 2 条记忆
├── ...                # 按序递增
├── 压缩归档.md        # 存放被压缩的旧记忆摘要（持续累积，不超过 500 字/条）
├── 术语表.md          # 项目专有名词定义（空间轴）
└── 决策记录/          # 不可逆决策及其理由
    └── ADR_001.md
```

**注意**：`Ai记忆库/` 目录位于**当前项目根目录**下，例如 `<project_root>/Ai记忆库/`。不在本技能里硬编码任何具体项目的绝对路径，实际路径以当前工作目录为准。

## 触发条件（何时调用）

以下情况**必须**调用本技能创建或更新记忆：

| 变更类型 | 示例 |
|---------|------|
| 架构改动 | 新增模块、重构目录结构、修改数据流 |
| 新功能 | 增加 API 接口、前端页面、后台任务 |
| Bug 修复 | 修复线上问题、逻辑错误、兼容性问题 |
| 部署配置变更 | Docker Compose 修改、环境变量调整、CI/CD 变更 |
| 依赖变更 | 新增/升级/移除关键依赖库 |
| 约定/规则建立 | 命名规范、代码风格、工作流程约定 |
| 术语定义 | 出现新的专有名词、术语口径变更 |
| 技术决策 | 技术选型、数据结构定型、主动放弃某方案 |

**以下情况可跳过**：单文件单行修改、纯注释变更、仅格式调整、非关键配置微调。

> 跳过仅适用于**记忆**。若改动涉及不可逆决策，或引入了新的专有名词，仍须写决策记录/术语表——这两者不受"小改动"豁免。

## 检索协议（何时读取记忆）

本技能不只是写入，任务开始前需要按下列顺序检索，避免重复踩坑或与既有约定冲突。**只读必要的部分，不要一次通读全部记忆文件**，否则失去拆分文件的意义。

| 场景 | 读取范围 |
|------|---------|
| 任意非微小任务开始前 | 仅 `索引.json`（成本可控，20 条摘要） |
| 项目根目录存在 `规格/` 时 | 先读 `规格/<主题>.md` 与 `规格/<主题>_任务.md`，承接既有结论，**不要重新设计** |
| 索引中命中相关关键词（模块名、文件路径、功能名） | 追加读取对应的 `记忆_XXX.md` |
| 涉及专有名词、口径、缩写 | `术语表.md`（体量小，通常直接整读） |
| 要改动技术选型、数据结构、对外接口 | `决策记录/`——**先看"排除了什么"**，避免重走已否决的方案 |
| 需要追溯更早历史（索引中已无该条目） | 读 `压缩归档.md`；仍不足则按压缩步骤第 4 条从 git 历史取回原文 |
| 任务完全独立、与既有代码无关（如纯新建示例） | 可跳过检索 |

命中判定以「摘要 + 相关文件路径」为准，不确定是否相关时**优先读**，因为漏读的成本高于多读一个文件。

## 索引.json 格式规范

纯中文 JSON 数组，每个元素包含三个字段：

```json
[
  {
    "序号": "001",
    "时间戳": "2026-07-01 02:30:00",
    "摘要": "初始化分布式文件夹记忆系统，拆分永久记忆.json 为独立 Markdown 文件"
  },
  {
    "序号": "002",
    "时间戳": "2026-07-01 14:25:00",
    "摘要": "新增用户登录模块，支持 JWT 认证"
  }
]
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `序号` | string | 数字编号，与文件名编号一致（三位补零，超 999 后为四位） |
| `时间戳` | string | 格式 `YYYY-MM-DD HH:mm:ss` |
| `摘要` | string | **一句话极其精炼的改动概括**，不超过 50 字 |

### 更新规则

1. **追加新条目**：每次新增记忆时，在数组末尾追加
2. **禁止修改历史**：已写入的条目不得修改、删除或重排。若某条索引或记忆内容确有错误，**不得直接改写**，应新建一条记忆说明更正
3. **刷新索引**：每次写入新的记忆文件后，同步更新 `索引.json`
4. **压缩时移除**：当触发自动压缩时，必须同步从 `索引.json` 中移除被压缩条目的索引（确保索引只映射当前活跃的 20 条记忆）

## 记忆_XXX.md 格式规范

### 文件命名

- `记忆_001.md`、`记忆_002.md`、`记忆_003.md` ... 依次递增
- 数字编号不足三位补零，超过 `999` 后按实际位数命名

### 文件内容结构

```markdown
# 记忆节点 #001

**触发时间**：2026-07-01 02:30:00

## 当前任务

一句话描述本次要完成的任务目标。例如：
> 将项目从单体 JSON 记忆文件重构为分布式文件夹记忆系统。

## 🔧 代码修改细节

按模块列出本次涉及的所有关键修改：

### 1. 模块名 / 文件名

- **修改内容**：xxx
- **原因**：xxx
- **关键代码段**（按需，通常 3-10 行）
  ```语言
  // 示例代码
  ```

### 2. 下一个模块 / 文件

- **修改内容**：xxx
- **原因**：xxx

## ⚠️ 避坑指南

记录本次遇到的关键问题和解决方案，供后续参考：

- ⚠️ 问题 1：xxx
  - 解决：xxx
- ⚠️ 问题 2：xxx
  - 解决：xxx

## 相关文件

- [文件路径](file:///absolute/path/to/file) - 说明
- [文件路径](file:///absolute/path/to/file) - 说明
```

### 内容编写规则

1. **# 记忆节点 #序号**：一级标题，保持与文件名编号一致
2. **触发时间**：改动的实际发生时间。**必须通过命令获取系统当前时间，禁止凭训练数据臆造日期**，例如：

   ```bash
   Get-Date -Format "yyyy-MM-dd HH:mm:ss"
   ```

   （非 Windows 环境用 `date +"%Y-%m-%d %H:%M:%S"`）所有记忆节点与归档条目共用同一时间来源，保证前后顺序不会被误判
3. **当前任务**：简述本次任务的目标，用 `>` 引用块包裹
4. **🔧 代码修改细节**：按模块分类列出修改内容、原因和关键代码。**不要遗漏任何有意义的修改**。但注意控制体积：代码已在 git 中留存，记忆里只放理解改动所必需的片段（通常 3-10 行），不要整段复制，能用一个函数名或 commit hash 说清的就不要贴代码
5. **⚠️ 避坑指南**：记录踩过的坑、特殊注意事项、决策原因。**这是关键留痕，对后续开发非常重要**
6. **相关文件**：列出本次修改涉及的所有文件，使用可点击的 `file:///` 绝对路径链接

## 工作流程

### 创建新记忆

1. 读取 `Ai记忆库/索引.json` 获取当前最大序号 `N`
2. 新序号 = `N+1`，格式化为三位数字（如 `008`）。若索引为空或缺失，则扫描 `Ai记忆库/记忆_*.md` 文件名取最大值；两者都无则为 `001`。序号超过 `999` 后自然进位为四位（如 `1000`），编号位数以实际值位数为准，不截断、不回绕
3. 创建 `Ai记忆库/记忆_XXX.md`，按格式规范填写内容
4. 在 `Ai记忆库/索引.json` 末尾追加新条目
5. **检查压缩条件**：如果独立文件总数（包括刚创建的文件）超过 20 个，按照"自动压缩机制"的步骤执行压缩
6. **验证**：确保索引和文件内容一致，文件可正常读取
7. **提交推送**：记忆落盘（含索引与压缩归档更新）后，**自动执行 git 提交与推送**：

   ```bash
   git add Ai记忆库/ .openhands/
   git commit -m "chore(memory): 落盘记忆_XXX"
   git push origin main
   ```

   **推送前置检查（缺一不可，不满足则跳过推送并在回复中说明原因）**：

   - 当前分支必须为 `main`（用 `git rev-parse --abbrev-ref HEAD` 确认），否则只提交不推送
   - 工作区不存在未解决的合并冲突
   - 远程推送失败（如非快进）时**不得**使用 `--force`；改为先 `git pull --rebase`，若仍有冲突则保留本地提交并告知用户

   **凭据规则**：origin 必须保持不含 token 的干净地址。认证走系统凭据管理器，**禁止**把 token 写入 `.git/config`、remote URL 或任何仓库内文件。若发现 token 已出现在上述位置或对话中，立即提示用户吊销。

### 初始化记忆库（首次使用）

1. 创建 `Ai记忆库/` 目录（如不存在）
2. 创建 `Ai记忆库/索引.json`，内容为 `[]`（空数组）
3. 现有历史记录按时间顺序从 `001` 开始编号

## 注意事项

1. 所有内容使用**纯中文**（代码和专有名词除外）
2. Markdown 中关键小节统一使用 `🔧 代码修改细节`、`⚠️ 避坑指南` 两个标题，便于视觉定位
3. **活跃记忆不可变**：已写入的 `记忆_XXX.md` 正文不得修改、删除或重排。唯一的例外是"自动压缩机制"——它会把最旧的活跃记忆提炼为摘要并删除原文件，这是归档转换而非篡改；如某条记忆内容确有错误，不得直接改写，应新建一条记忆说明更正
4. 文件路径使用 `file:///` 协议 + 绝对路径，方便 IDE 跳转
5. 单文件单行修改、纯配置调整、仅注释变更等视为小改动，可跳过记忆
6. **落盘即推送**：每次创建或更新记忆后，自动执行 git 提交并按上述"推送前置检查"推送到远程仓库（origin/main），避免本地记忆与远程仓库脱节

## 术语表与决策记录

记忆是**时间轴**（发生了什么），术语表与决策记录是**空间轴**（现在是什么、为什么这样）。三者互补，不要混写。

### 术语表.md

统一项目用词，避免 AI 用通用词替代专名。**新概念先在术语表定义，再在规格或记忆里使用**（grill-me 拷问、to-spec 写规格时尤其需要）。

```
| 术语 | 定义 | 首次出现 |
|------|------|---------|
| 记忆节点 | 一次改动的完整留痕，对应 记忆_XXX.md | 记忆_001 |
```

**只收录**：项目专有名词、容易被通用词替代的概念、有歧义的缩写。通用编程术语不要收录。

### 决策记录/

与记忆的区别：记忆记录"做了什么"，决策记录回答"为什么这么定、当时排除了什么"。

**新增条件（满足其一）**：技术选型、数据结构定型、对外接口约定、主动放弃某方案。

`决策记录/ADR_XXX.md` 格式：

```
# ADR_XXX：<决策一句话>

- 日期：YYYY-MM-DD
- 状态：生效 / 已废弃（被 ADR_XXX 取代）

## 背景
面临什么选择，约束是什么。

## 决定
选了什么。

## 理由
为什么选它。

## 排除了什么
考虑过但没选的方案及原因。**这一节最重要**——后续想推翻决定时先看这里。
```

**已生效的决策记录不可改写**；决定变化时新建一条 ADR，把旧的标为"已废弃"并互相链接。

## 压缩归档.md 格式规范

被压缩的旧记忆摘要存放在 `压缩归档.md` 中，格式如下：

```markdown
- [2025-01-01 10:00] 修复了登录接口的超时问题，将 timeout 从5s调至30s。
- [2025-06-15 14:30] 新增用户注册模块，支持邮箱验证码和 JWT 登录。
```

### 字段说明

| 部分 | 说明 |
|------|------|
| `时间` | 格式 `YYYY-MM-DD HH:mm`，使用方括号包裹 |
| `摘要内容` | 中文摘要，**不超过 500 字**，必须保留时间戳和关键决策点 |

> 注意区分两个摘要的粒度：`索引.json` 的 `摘要` 是**索引级**，不超过 50 字；`压缩归档.md` 的条目是**归档级**，不超过 500 字。两者不要混用。

### 更新规则

1. 按时间顺序排列，最新的追加到末尾
2. 每条摘要不超过 500 字
3. 内容一旦写入不再修改

## 自动压缩机制

### 容量上限

`Ai记忆库` 根目录下，未压缩的独立 `记忆_XXX.md` 文件**最多保留 20 个**（即编号最新的 20 条）。

### 触发条件

当新增一条记忆，导致独立文件总数超过 20 个时，**立即执行压缩**。

### 压缩对象

每次压缩**当前编号最小（即时间最久远）**的那条独立 `记忆_XXX.md` 文件。

**压缩执行步骤（严格按顺序）**

1. **读取**：读取该文件的完整内容（触发时间、任务、细节、避坑指南）
2. **提炼摘要**：将其核心信息提炼为一段**不超过 500 字的中文摘要**（必须保留时间戳和关键决策点）。如果内容非常重要，允许超过 500 字但**不得超过原文件的 1/3**。压缩目标是下一个 AI 读了也能基本了解项目该阶段全貌
3. **追加归档**：将该摘要按时间顺序追加写入 `Ai记忆库/压缩归档.md`
4. **删除文件**：删除该 `记忆_XXX.md` 独立文件（**不保留 `已压缩/` 目录**。因"落盘即推送"要求，被删除文件的完整原文永久留存于 git 历史中，需要追溯细节时用 `git log --diff-filter=D --name-only -- 'Ai记忆库/记忆_XXX.md'` 定位后 `git show <commit>:<path>` 取回，无需另设目录）
5. **更新索引**：从 `索引.json` 中移除该条目的轻量索引（确保索引只映射当前活跃的 20 条记忆）
6. **编号继续递增**：后续新增的文件编号继续递增（如删除了 001，新文件编号为 022，无需重排旧编号）
