## 🔧 代码修改细节

### 1. `src/evm/batch.ts`（新增，纯编排）

- `parseRecipients`：每行一个地址，忽略空行/`#` 注释，非法地址带行号返回。
- `buildPlan`：`one-to-many` = 单发送钱包 × 全部地址；`many-to-one` = 全部发送钱包 × 单地址；缺发送方/收款方/金额直接抛错。
- `runBatch`：按 `from` 分组，同一钱包严格串行，不同钱包最多 3 并发；每笔广播前 `precheck`；广播后状态 `success/failed/unknown`。
  - 返回 `pending`（结果不明）时停止该钱包后续笔，剩余笔标 `failed` + `broadcasted:false`（可重试）。
  - `send` 调用抛错时无法判断请求是否已到 RPC/bundler，按 `unknown` + `broadcasted:true` 处理并停止该钱包后续笔（宁可人工核对，不自动重发）。
  - `minIntervalMs` 节流（AA 1500ms / BSC 800ms），`sleep` 可注入便于测试。
- `isRetryable`：只认 `failed && !broadcasted`；已广播失败/结果不明一律不自动重发。
- `recoverBatch`：页面重开后 `signing/submitting/waiting` → `unknown` + `broadcasted:true`，绝不假装成功。

## ⚠️ 避坑指南

- ⚠️ **余额为 0 时 `eth_estimateGas` 会抛 `EVM error: OutOfFunds`**：BSC 预检必须先查余额再估算 gas，否则错误文案不可读。
- ⚠️ **回执查询失败 ≠ 交易失败**：BSC 广播后查询异常必须返回 `pending`（结果不明），否则批量会重复转账。
- ⚠️ **`pending` 后不能继续同一钱包下一笔**：nonce 未确认，继续发会冲突；剩余笔标失败但未广播，需先核对链上再重试。
- ⚠️ **重试项要沿用原序号**：`BatchPlanItem.index` 可选，执行器用 `item.index ?? 顺序号`，否则重试后列表序号跳回 #1。
- ⚠️ **localStorage 只放批次元数据**：地址/金额/哈希可以，私钥/密码/PRF 绝对不行。
- ⚠️ **`npm run dev` 与 `npm run build` 的 target 要一致**：libsodium ESM 有 top-level await，Vite 预构建默认 es2020 会直接启动失败。
