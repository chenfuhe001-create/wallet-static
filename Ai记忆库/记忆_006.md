# 记忆节点 #006

**触发时间**：2026-11-25 23:52:58

## 当前任务

> 用户批量转账遇到「发送结果不明：Failed to fetch」。定位并修复：区分广播前失败与广播调用失败；广播前失败可直接重试；增加网络诊断与发送地址核对入口；页脚显示构建时间。

## 🔧 代码修改细节

### 1. 失败分类（`src/rpc.ts`）

- 新增 `PreBroadcastError`：读 RPC、估算 gas、签名阶段的失败，交易**肯定没发出**，可安全重试。
- 保留 `BroadcastError`：已上链但执行失败，带 hash，禁止重发。

### 2. 发送函数包裹（`src/evm/native.ts`、`src/evm/op.ts`）

- `sendNative` / `sendAaTransfer` 增加 `broadcastStarted` 标记：在真正调用 `eth_sendRawTransaction` / `eth_sendUserOperation` 前置为 true。
- 广播前的任何异常统一包成 `PreBroadcastError(\`${chain.short} 发送前失败：…\`)`；广播调用本身的异常保持原样（结果不明）。
- 回执查询异常仍返回 `pending`（BSC）/ `unknown`（AA），不重发。

### 3. 批量执行器（`src/evm/batch.ts`）

- `PreBroadcastError` → 该笔 `failed` + `broadcasted:false`（可重试），继续下一笔，不阻塞同钱包。
- 其它广播异常 → `unknown` + 停止该钱包后续笔（nonce 不明），保留人工核对。

### 4. 界面（`src/BatchPanel.tsx`、`src/App.tsx`、`vite.config.ts`）

- 新增「网络诊断」：当前链 `eth_chainId` + 原生 gasPrice / Pimlico bundler gas；链 ID 不匹配直接报错。
- 失败/结果不明项显示「核对发送地址」链接（`/tx/` 替换为 `/address/`）；`unknown` 且无哈希时提示先看 nonce。
- 页脚显示构建时间（`__BUILD_TIME__`，UTC），用于确认 Pages 是否为新版本。

### 5. 诊断结论

- 从已部署的 `https://chenfuhe001-create.github.io/wallet-static/` 实测：18 个 RPC 端点 + 7 条 Pimlico bundler 的 POST 全部可通，无 CSP/CORS 拦截；因此本次 `Failed to fetch` 是瞬时传输失败，不是域名白名单问题。
- 旧版本把「发送调用抛错」一律当结果不明；新版本把签名/读 RPC 阶段的失败归为可重试，避免再次卡住。

### 6. 验证

- `tests/batch.test.ts` 新增「广播前网络失败可重试」；`npm test` **5 个文件 33 条全绿**。
- 浏览器（dev）：网络诊断返回 `RPC 正常（chainId 56）；gasPrice …`；余额不足项显示「失败 + BNB 余额不足以支付金额 + 核对发送地址」，重试按钮可用，无控制台错误。
- `npm run build` 通过，`docs/` 已同步。

## ⚠️ 避坑指南

- ⚠️ **`Failed to fetch` 是传输层错误**：不是 HTTP 状态码，也不一定是 CORS/CSP；移动网络抖动、连接被重置都会出现。先跑「网络诊断」，再判断是否重试。
- ⚠️ **只有广播调用本身失败才叫结果不明**：读 nonce/gas/余额、签名失败都发生在广播前，重试不会双花；不要把整段都标 unknown。
- ⚠️ **`rpcRead` 会依次尝试 fallback**：最终错误可能来自最后一个端点，错误文案里没有具体 URL；诊断时用 `rpcCall` 单端点或逐端点测。
- ⚠️ **GitHub Pages 有缓存**：新构建可能要强刷；页脚构建时间是最快的版本确认方式。
- ⚠️ **结果不明且无哈希时不要直接重发**：先看发送地址的 latest/pending nonce 与最近交易；确认没发出再清记录重试。
