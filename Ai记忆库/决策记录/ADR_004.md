# ADR_004：允许按需导出比特币 WIF，但强调共享 EVM 密钥风险

- 日期：2026-11-28
- 状态：生效
- 关联：记忆_013、`src/bitcoin/export.ts`、`src/BitcoinWorkspace.tsx`

## 背景

比特币地址由现有 secp256k1 私钥派生为 P2WPKH（`bc1q…`）。用户想把 BTC 导进其他钱包，但应用原先只展示 EVM hex 私钥；比特币钱包通常只接受 WIF，且很多钱包默认按 Legacy/P2PKH 解析，导致地址不匹配、余额显示为 0。

## 决定

1. 在 Bitcoin 工作区提供「导出到其他钱包」：标准 WIF 与 `p2wpkh:<WIF>` 两种形式，各带二维码与复制。
2. 必须用户显式确认后才显示；60 秒自动清除，切换钱包/锁定/卸载立即清除；不写 localStorage、不发网络、不打日志。
3. 明确提示 **WIF 等同 EVM 私钥**：导入第三方钱包会同时暴露 EVM 资产；优先推荐新建独立钱包后 sweep。
4. 文档给出 BlueWallet/Electrum（`p2wpkh:` 前缀）、Sparrow（Sweep + Native SegWit）、Bitcoin Core（`wpkh(WIF)` 描述符，高级）与「只支持助记词的钱包必须 sweep」的路径。
5. 不导出 descriptor/xprv，不生成新的 BIP39/BIP84 钱包，不做自动 sweep/全部转出。

## 理由

- WIF 是单钥导入的事实标准；`p2wpkh:` 前缀能让 Electrum/BlueWallet 明确按 Native SegWit 解析，避免落入 Legacy。
- 共享私钥不能通过换格式消除风险；导出功能必须把「同源 EVM 私钥」讲清楚，降低用户把热钱包当长期方案的概率。
- 60 秒 + 确认弹窗沿用现有私钥二维码的安全习惯，避免 WIF 长期停留在 DOM。

## 排除了什么

- **自动导出/持久化 WIF**：增加泄露面，且用户没有随时需要它的场景。
- **导出 uncompressed WIF / Legacy 地址**：会让用户误以为 `1…` 是同一个地址，余额对不上，问题更大。
- **导出 descriptor/xprv**：本期只解决单钥导入；描述符更适合高级用户，后续单独评估。
- **在应用内生成新 BIP39 钱包**：涉及新的助记词安全模型，超出本期范围；推荐用成熟钱包 sweep。
