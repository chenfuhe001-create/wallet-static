# 从规格到任务

把 `规格/<主题>.md` 拆成一组**可独立验证的纵向切片**。

## 铁律：纵向切片，不按技术层切

❌ 错误切法（按技术层）：

- T1：设计所有数据表
- T2：实现所有 API
- T3：写所有前端页面

问题：每个切片单独都无法验证，必须等全部做完才能测。

✅ 正确切法（纵向切片 / 演练子弹）：

- T1：用户能创建一条记录（表、接口、界面全都只覆盖这一条路径）
- T2：用户能查看列表
- T3：用户能删除记录

每个切片打通一条**从用户操作到数据落库的完整细线**，做完即可点开验证。

**第一个切片应是最小可运行的骨架**，先打通最细那条通路，再逐条加宽。

## 任务文件格式

写到 `规格/<主题>_任务.md`：

````markdown
# <主题> 任务清单

## T1：<用户可见的一句话结果>
- 覆盖行为：规格第 X 条
- 阻塞于：无
- 验证方式：<可执行的动作>
- 状态：待办

## T2：<用户可见的一句话结果>
- 覆盖行为：规格第 Y 条
- 阻塞于：T1
- 验证方式：<可执行的动作>
- 状态：待办
````

## 规则

1. **标题写"用户能做什么"**，不写"实现了什么模块"。
2. **声明阻塞边**（阻塞于）。无阻塞的任务即当前可并行推进的前沿。
3. **验证方式必须是可执行动作**，不是形容词。
4. **一个任务只服务一条规格行为**，跨多条就拆开。
5. **不写实现步骤。** 任务定义"做到什么"，不定义"怎么改代码"——留给实现阶段。

## 完成标准

- 每个任务都能单独验证，不需等别人
- 不存在"必须全部做完才能测"的任务
- 每个任务都能追溯到规格里的具体条目
- 阻塞关系无环
