你的技能在项目根目录的 `.openhands` 这个文件夹里面（注意是 `.openhands` 不是 `.trae`），你必须完全读取并遵守里面的 skills。

## 执行要求

1. **先读后做**：在开始任何任务前，先读取 `.openhands/skills/` 下每个技能目录的 `SKILL.md`（以实际存在的目录为准，当前为 `memory`、`skill-guide`、`writing-great-skills`、`grill-me`、`to-spec`、`to-tickets`、`tdd`、`code-review`），以及后续新增的任何技能。
2. **立即执行，避免无谓确认**：读取技能后直接按技能流程开始执行。不要输出"要不要继续"、"是否现在开始"、"需要我做吗"这类**仅用于确认是否动手**的问句，也不要在可自行判断的步骤之间停顿等待确认。
3. **必须提问的场景（有限例外）**：以下情况**必须**先停下来问用户，并给出具体选项：
   - 涉及不可逆的破坏性操作（删除文件、`git push --force`、`git reset --hard`、格式化等）
   - 需求存在歧义，且不同理解会导致明显不同的实现方向
   - 缺少必要凭据、权限或关键环境信息，无法继续
   - 检测到密钥/token 等敏感信息已出现在代码、配置或对话中（此时应提示用户吊销）

   **豁免**：某个技能已明确规定的常规操作不算"需要提问"，按其流程直接执行。例如 memory 技能的自动压缩会删除最旧的记忆文件——这是技能定义的归档流程，且原文已永久留存于 git 历史，无需每次询问。
4. **强制语义**：技能中的 `必须`、`立即`、`禁止` 按字面执行；出现 `可以`、`建议`、`尽量` 时也按强制理解。
5. **不创建无关文档**：不要生成与 `.openhands/skills/` 内技能无关的说明文档。
6. **清理测试产物**：测试过程中产生的临时文件、脚本、样例数据，在任务结束时清理干净。
7. **冲突优先级**：当多个技能的要求互相冲突时，按以下顺序取舍——安全与凭据规则 > 用户在当前对话中的显式指令 > 本文件的通用要求 > 具体业务技能。无法判断时按第 3 条提问。
8. **技能回写**：若执行中发现某个技能的内容与项目实际情况不符（如路径、命令、仓库地址已变化），应在本次任务中**同步修正该技能文件**，而不是绕开它继续执行。

## 流程链

多个技能串成一条链，覆盖"从模糊想法到已验证代码"。**按需进入，不必每步都走**：

````
grill-me ──→ to-spec ──→ to-tickets ──→ 实现 ──→ code-review
（拷问需求）  （固化规格）   （拆纵向切片）   ↑        （独立审查）
                                       tdd
                                   （红绿门禁）
````

| 步骤 | 技能 | 进入条件 |
|------|------|---------|
| 1 | grill-me | **仅用户明确要求拷问时**（触发词由该技能定义）。需求歧义但不要求拷问时，只走第 3 条轻量澄清 |
| 2 | to-spec | 有共识需要固化，或任务将跨多次会话 |
| 3 | to-tickets | 规格已确认，需要拆解 |
| 4 | tdd | 编写或修改可测试代码 |
| 5 | code-review | 实现完成、提交前 |

**memory 贯穿全程**：每步开始前按检索协议读，结束后落盘。它不属于链条本身，是横切层。

**小改动可只走第 4 步。** 只改一行配置就别启动整条链。

## 技能间关系

- `grill-me` 只按触发词激活；**轻量需求澄清**由本文件第 3 条负责，两者不要混用
- `to-spec` 的规格是 `to-tickets` 与 `code-review` 的验收依据，三者必须使用同一套词汇（术语表）
- `writing-great-skills` 是元技能：新增或修改任何技能文件后，用它自查
